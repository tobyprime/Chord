# Chord — 需求与技术方案（v0.2）

> 客户端 Mod 提供乐器演奏，服务端插件以原生音频广播：**只有演奏者需要安装模组，聆听者零安装即可听到。**

- 日期：2026-10-06（v0.2：第二轮需求确认后更新）
- 状态：核心需求已锁定，待进入工程搭建

---

## 1. 目标与非目标

### 目标
- 演奏者安装客户端 Mod，在服务器内实时演奏乐器（首发：口琴，参考三角洲行动「守夜人口琴」）
- 聆听者为原版客户端，无需安装任何模组即可听到演奏
- 服务端为 Folia（Paper 系）插件，负责音频广播与校验
- 乐器与音色的映射**全部可配置**，服务端热更新配置即可换音色/加乐器，客户端零改动
- 音色由**服务器自定义资源包**承载，按全音域真实采样设计（见 §7）；音频资产与资源包分发由服务器既有体系负责，本项目只约定事件命名规范并消费

### 非目标（V1 明确不做）
- 不做自动演奏/曲目导入（二期）
- 不做多乐器同时首发（架构上预留，V1 只出口琴）
- 不负责资源包/音频资产的制作与分发（由服务器侧维护）
- 不做基岩版(Geyser)专项适配（预计兼容，顺带验证）

---

## 2. 总体架构

```
[演奏者]                                          [聆听者们]
 Chord 客户端 Mod                           原版客户端（零安装）
  · 演奏态/键位/音域逻辑                        · 只收 PlaySound 包放音
  · 第一人称口琴渲染                             ▲
  · 本地校验+发包                    PlaySound(原版SoundEvent, pitch)
     │ Custom Payload                           │
     ▼ chord:play 频道                           │
 Chord 服务端插件 (Folia) ─ 校验/限速/映射 ── world.playSound()
     ▲
  config: 乐器定义 / 音色映射 / 音域 / 限速 / 权限
     │ chord:sync 频道（下行）
     └────────── 向客户端下发乐器定义（握手）
```

核心链路：客户端按键 → 算出「乐器 id + 半音偏移」→ 发 `chord:play` → 插件按配置映射成 SoundEvent + pitch → `world.playSound()` 广播给范围内所有玩家。

设计原则：**客户端保持"哑终端"**——只发 (乐器id, 半音)，所有音色/音域/音量决策在服务端配置。这保证"可配置映射"天然成立，改配置不用发新版 Mod。

## 3. 版本与生态（已确认）

| 项 | 决定 |
|---|---|
| Minecraft 版本 | Java 26.2（客户端与服务端同版本线） |
| 服务端 | Folia 26.2（Paper 系分支） |
| 客户端加载器 | **Fabric（已确认）**——对新版本跟进最快、客户端轻量 |
| 插件形态 | Folia 插件，`plugin.yml` 声明 `folia-supported: true` |

Folia 特别注意：

- `world.playSound` 在玩家所在区域线程执行即可（消息处理回调自带玩家实体上下文）

## 4. 通信协议（Mod ↔ 插件）

Plugin Message 自定义频道（Bukkit Messenger + Fabric 自定义 payload）：

| 频道 | 方向 | 用途 |
|---|---|---|
| `chord:play` | C2S | 演奏一个音符 |
| `chord:auto` | C2S | 自动演奏会话通告（开始/结束，携带曲名；服务端据此做「非现场弹奏」提示） |
| `chord:pedal` | C2S | 延音踏板踩下/松开（仅 sustain 释放模式乐器如钢琴；v5） |
| `chord:sync` | S2C | 握手：下发乐器定义表 |
| `chord:poly` | S2C | 乐器复音容量表（MIDI 单音收敛阈值；随 sync 一并下发；0.7.5 兼容扩展） |
| `chord:enter` | S2C | 进入/退出世界乐器演奏态（如钢琴交互实体，锚点坐标随行） |
| `chord:settings` | C2S | 玩家个人设置（如屏蔽某人演奏的偏好同步，预留） |

`chord:play` 载荷（紧凑二进制）：
```
u8  instrumentId   // 乐器 id（由 sync 表分配）
i8  semitone       // 相对该乐器中心音的半音偏移（有符号）
u8  velocity       // 力度 1~127（100=基准音量；v6 起）；note-off 时无意义（0）
u8  flags          // bit0 = note-off（松键）；bit1 = auto（乐谱自动演奏的音）；
                   // bit2 = force-stop（硬止音，与 bit0 同用：闷音键/退出演奏态掐掉余音）
                   // bit3 = sustain（延音踏板踩下期间的松键，仅 sustain 乐器：转余音而非制音）
                   // 其余位保留，非 0 即丢弃
```
力度双通道语义：服务端按 `layers:`（力度分层采样）路由音色 + 按力度缩放音量（100=×1.0，
127≈×1.27，下限 ×0.1）。输入源无关——普通键盘用滚轮调档（全局力度），磁轴键盘等模拟
输入源（V2 适配器）按行程速度给逐键真实力度，走同一字段。

`chord:auto` 载荷：
```
u8   action        // 1 = 开始 / 0 = 结束
UTF  title         // 曲名（≤64 字符；结束时可为空）
```

`chord:sync` 载荷（玩家入服或客户端 REGISTER 频道时下发）：
```
u8      count
repeat: {
  u8      instrumentId
  string  key / displayName
  i8      minSemitone / maxSemitone   // 服务端允许的音域
  u8      flags                       // bit0 = 松键有余音语义（decay/sustain）；bit1 = sustain 模式（钢琴：K=延音踏板）
  u8      labelRuleCount              // v4 起：半音区间显示名规则（鼓件名）
  repeat: { i8 min / i8 max, string label }
}
u16  protocolVersion  // 版本不匹配时客户端禁用演奏并提示升级
```

`chord:poly` 载荷（紧随 chord:sync 下发，0.7.5）：
```
u8  count
repeat: { u8 instrumentId, u8 maxPolyphony }   // 复音容量：MIDI 转换自动单音收敛阈值
```
不放进 sync 的 InstrumentDef：旧客户端（≤0.7.4）的 SyncPayload.fromBytes 对载荷多余字节
严格报错，追加字段会让所有已发布客户端整表解析失败；独立频道对未注册它的旧客户端是
静默丢弃，新旧客户端/服务端四个组合方向全部兼容。未收到本表（旧服务端）时客户端按
释放模式兜底（sustain 乐器 10，其余 6）。

要点：
- 频道名必须带命名空间（`chord:` 前缀），这是 Paper Messenger 的硬性要求
- 每音符一包，几字节；和弦 = 同刻多包，无需合包
- 协议版本 4（0.4.0）：InstrumentDef 追加 labelRuleCount/label 规则（服务端 instruments.yml 的 voice 行 `label:` 下发；无标签的乐器 count=0，客户端回退音级名）
- 协议版本 5（0.5.0）：chord:pedal 频道 + NotePayload bit3（sustain 松键）+ InstrumentDef bit1（sustain 模式）
- 协议版本 6（0.6.0）：NotePayload 加 u8 velocity（力度）+ 服务端 layers 力度分层路由与音量缩放；旧载荷长度不同，两端成对更新
- v6 兼容扩展（0.7.5）：chord:poly 复音容量表（上表）；sync 线格式与 PROTOCOL_VERSION 均不动
- 26.x 的 Fabric 网络 API（1.20.5+ 改版后的 CustomPayload 体系）写法以实际 Fabric API 版本为准，实现时验证

## 5. 演奏操作（已确认：复刻三角洲键位）

与三角洲行动口琴一致的三层结构：

**进入演奏态**有两种方式（乐器由配置的 `entry` 决定，`item` 或 `world`）：
- **手持乐器物品右键举起（item，口琴等）**：进入演奏态；客户端本地拦截该物品的原生使用动作。移动仍可走动（不疾跑）。**蹲下+右键例外**：放行原版交互不拦截（手持乐器时仍可放置 CraftEngine 家具等）——蹲下本身即演奏态退出条件，与举起天然互斥；服务端兜底取消同样按蹲下放行（原版客户端蹲下持乐器会触发原生山羊角音，是放行的已知代价）。
- **右键世界装置（world，钢琴等）**：对着插件放置的带标记交互实体右键，标记判定在服务端（实体 PDC），服务端经 `chord:enter` 通知装了 Mod 的客户端进入演奏态；原版玩家收到提示文案。退出：蹲下或离开装置 8 格（客户端锚点自动退出 + 服务端音符就近校验双层）。

**退出演奏态**：蹲下（两种模式通用）或 切换快捷栏（仅 item 模式；右键**不能**作为退出键——演奏态内右键已被占用为八度修饰键）。

**键位布局**（演奏态内，默认=三角洲布局）：
```
Z X C V B N M ,   →  八个音级，半音偏移 0 2 4 5 7 9 11 12（简谱 1 2 3 4 5 6 7 高音1）
按住鼠标左键      →  整排 −12（降八度）
按住鼠标右键      →  整排 +12（升八度）
按住鼠标中键      →  整排 +1（升半音；可与左/右叠加）
```
- **直排音键（自定义半音）**：游戏内「配置界面」键（默认 J，任意时刻可开）可视化编辑——16 个槽位，每行开关 + 半音步进（Shift ±12，范围 −24~+32）+ 显示名，**保存即热应用**（重建按键槽，正在演奏先退出）；物理键在原版「控件设置 → Chord 乐器」绑定，**默认全部制空**。持久化为 `config/chord.json`（可手改，重启生效）。适合钢琴式双排布局（白键 Z 行、黑键 A/S/D 行：Z=1、S=1♯、X=2、D=2♯…），直排音与八度/半音修饰键照常叠加。直排音不要与音级键绑同一物理键（槽位按顺序先匹配先生效），做全直排布局时把对应音级键解绑即可
- 音高 = 键槽基础半音 + 12×shift + sharp，默认音级键覆盖 38 个半音、完全半音阶（实际音域以服务端 sync 下发为准）
- 超出服务端下发音域的键位组合：本地直接静音（不发包），UI 灰显提示
- 演奏态内鼠标三键被 Mod 接管（禁用攻击/使用原逻辑），松开演奏态即恢复
- **修饰键变调（宽限窗口制，150ms）**：修饰键**只影响新按下的音**；唯一例外是按音后 150ms 内的修饰键按下/松开——视作「本来就想同时按」，按住中的音立即修正到新音高（覆盖「先按音再极短补修饰键」的快速操作，按下/松开两个方向都修正）。窗口外修饰键变化不动已按住的音：松开高音不回落（已发的音不换调，真实乐器语义），按下高音也不跳（作为预备下一音）；下次按键才用新八度。宽限内修正后超出音域的音静音保持，修饰键在宽限内回到音域即自动恢复
- **释放行为按乐器区分（instruments.yml 的 release-mode，0.5.0 三态）**：
  `stop`（默认，口琴）= 松键立刻止音，气息乐器嘴离开就停；
  `decay`（吉他/贝斯/鼓）= 松键只是释放琴键、采样自然衰减出音尾，**闷音键**（默认 K）一键掐掉；
  `sustain`（钢琴）= **真钢琴制音器语义（0.5.0 按用户反馈重做）**：默认松键即制音（150ms 制音器落弦缓冲，期间被同半音重击或踏板踩下「接住」则取消——还原制音器先落弦再击弦、踏板时机捕捉），**K = 按住生效的延音踏板**：踩住期间松键的音转余音表延续、松开踏板掐掉所有「键已松开」的余音（按住中的键不受影响）。
  退出演奏态/断线一律硬止音干净收场。服务端限制余音并发 24 条（0.5.0 从 12 放宽：踏板期间合法堆叠），超出掐最旧（防刷）
- **自动演奏（客户端 MIDI 文件，0.7.15 起唯一来源）**：演奏态内按「自动演奏」键（默认 G，可改键）打开 MIDI 中心（顶部实时输入设备选择 + 曲目列表），点曲目按谱面自动演奏，播放中再按一次停止；HUD 空闲时常驻入口提示（键名跟随改键）。客户端引擎按谱面毫秒时刻调度 note-on/note-off（与手动演奏同一协议路径，音符带 `auto` 标记），HUD 显示小节/音符进度；手动按任意演奏键立即接管（停自动）、退出演奏态即停。修饰键变调不作用于自动演奏（谱面即绝对音高）。乐谱书副手自动演奏（0.2.0 落地）已于 0.7.15 全线移除

**键位可重映射（已确认）**：所有动作均可在客户端配置中改键——8 个音级键、3 个鼠标修饰键、举起动作、（可选的）专用退出键。V1 提供配置文件（JSON，含注释说明），V1.1 加游戏内设置界面。重映射只改「哪个物理键触发哪个动作」，不改变音高计算模型。

**反馈 UI**：屏幕下方显示当前按下的音名/简谱；连击提示（可选，后期）。

## 6. 乐器物品方案（已确认：基于物品 custom data 识别）

- **识别**：物品携带 `minecraft:custom_data` 组件标记，实现走 Bukkit PDC（自动持久化到 custom_data 的 `PublicBukkitValues` → `chord:instrument` 字符串路径），客户端 Mod 与插件**都以此标记识别乐器**，与物品底子类型解耦
- **底子物品**：默认山羊角（`minecraft:goat_horn`），原版旁观者看到演奏者手持山羊角，观感天然合理；底子类型进插件配置
- **发放**：插件提供 `/chord give <乐器> [玩家]`（权限 `chord.admin`），物品由插件生成并打标
- **原生行为拦截**：双层——客户端 Mod 本地拦截山羊角原生吹奏；插件侧 `PlayerInteractEvent` 兜底取消（防止未装 Mod 者拿着标记物品触发原版音效）
- **演奏者视角**：演奏态激活时，Mod 用自定义第一人称模型替换手持渲染（举起口琴贴嘴）；非演奏态显示原版山羊角，避免与原版模型系统打架（26.x 物品模型定义机制较新，第一人称覆盖渲染是更稳的路线，实现时再评估 `item_model` 组件方案）
- **世界乐器承载（world entry，钢琴等）**——按装置来源分两条路，都是声明式 `world-bind`（match-values 存家具/实体标识，match-regex 通配）：
  - **CraftEngine 家具（事件接入，软依赖）**：当前 CE 的 `type: interaction` 命中箱是**包级虚拟实体**（服务端无 Bukkit 实体、无 PDC，PlayerInteractEntityEvent 也不触发），右键由 CE 包监听器截获并先触发 `FurnitureInteractEvent`（携带家具 id，如 `example:player_piano`）。Chord 软依赖 CE 监听该事件：id 命中 world-bind → 开**位置锚点**演奏会话（家具位置，虚拟实体无实体可查）+ 经 chord:enter 进入演奏态，并取消事件接管右键（CE 配置的 right_click 占位动作跳过）。家具右键对装模组者即进演奏态、对原版客户端出安装提示；未命中 world-bind 的家具完全不受影响
  - **真实交互实体（PDC 匹配）**：实体 PDC 任意字符串值/自定义名命中 world-bind 即视为该乐器（旧版 CE 或其他家具插件的命中箱若为真实实体仍走此路）；`/chord piano inspect` 打印实体实际标识以便配置。兜底：`/chord piano spawn` 生成自带 chord 标记的实体，或 `bind`/`unbind` 手动标记
  - 音符校验为**会话制**：进入时记住锚点（实体实时位置或家具位置），演奏必须仍在锚点 8 格内；实体被拆除（实体锚点）即自动失效——无持久化登记表、无状态漂移。CE 家具拆除后位置锚点仍在，玩家走远才失效（已知边界，后续可接 CE 移除事件收紧）
- **乐谱书/演奏录制（已移除的历史方案）**：成书（written_book）PDC 路径 `chord:score` 承载 CHSC Base64 谱面 + `/chord score <import|info|transpose>` 命令 + `/chord blank` 空白书被动录制，0.2.0~0.7.10 存在；0.7.11 移除服务端侧，0.7.15 移除客户端播放与 CHSC 编解码（存量书按普通成书处理）。谱现为客户端内存对象：`.mid` → MidiConverter 现转现播（§13）

## 7. 音色方案（已确认：服务器自定义资源包，全音域采样设计）

音色**完全由服务器资源包的自定义 SoundEvent 承载**，本项目不制作/分发音频资产，只约定规范并由插件配置路由。

**全音域设计——按音区分层采样**：原版客户端对每个 SoundEvent 的音高钳制仍是 [0.5, 2.0]（约 2 个八度/事件，26.2 需实测确认），突破办法是采样乐器的常规手法：
- 每个乐器按音区录制多组采样（如低/中/高三个音区），每组注册一个 SoundEvent，负责约 2 个八度
- 同乐器各层采样音色一致，拼接后覆盖全音域（口琴建议 ≥ 3 个八度，覆盖三角洲同级的 38 半音并可更宽）
- 音区交界处允许 1–2 个半音的层间重叠，插件按 `voices` 表路由，避免边界跳变

**事件命名规范**（约定，资源包按此实现）：
```
chord:<乐器>.<锚点>        例：chord:harmonica.c4（0.7.14 起口琴 12 锚点 C3~G6）
```

**实际采样资产（V1 已就绪，见 `assets/resourcepack/`）**：VCSL（CC0）Hohner Super 64 半音阶口琴，三音区实测 C3 / E4 / G5（中心音 C4），拼接覆盖 C2–G6：
```yaml
harmonica:
  display-name: "守夜人口琴"
  base-item: GOAT_HORN
  semitone-range: [-24, 31]           # 采样全域（C2~G6）：低低1~高高5，经 direct_notes 直排音键可及
  volume: 1.0
  category: RECORDS
  voices:
    # 0.7.14：12 锚点 C3~G6 逐半音就近路由（此处示意前 4 层，完整表见 instruments.yml）
    - { min: -24, max: -10, sound: "chord:harmonica.c3.%d", base-pitch: 2.0029 }  # 采样 C3
    - { min: -9,  max: -7,  sound: "chord:harmonica.e3.%d", base-pitch: 1.5924 }  # 采样 E3
    - { min: -6,  max: -3,  sound: "chord:harmonica.g3.%d", base-pitch: 1.3369 }  # 采样 G3
    - { min: -2,  max: 2,   sound: "chord:harmonica.c4.%d", base-pitch: 0.9993 }  # 采样 C4
  fallback-voices:
    - { min: -12, max: 12, sound: "block.note_block.bit", base-pitch: 1.0 }
```
- `pitch = basePitch × 2^(semitone/12)`，服务端换算并钳制 [0.5, 2.0]（待真机复测，历史行为稳定）；音域放开到采样全域后默认音级键仍可达 [−12, +25]，更高/更低的音（低低音/高高音）由直排音键绑定演奏，极端变速（±12 之外）音色会被拉宽/压窄——采样乐器的正常表现。钢琴同理：C2（−24，低低1）~ G#6（+32，高高5♯）
- **按聆听者定向回退（V1.2）**：通过资源包状态识别未接受资源包的玩家，改发 `fallback-voices`
- **note-off（按住持续、松开即停）**：voices 的 `sound` 使用逐音符事件模板（含 `%d`，如 `chord:harmonica.c4.%d`）——资源包为每个半音注册独立事件（全部指向该层同一采样文件），服务端 note-on 时记录活跃音符与听众快照，note-off 时对该半音专属事件 `stopSound`，和弦中其他音不受影响；客户端崩溃未发 note-off 时表项 10 秒惰性过期兜底（采样最长 3.2s 自然结束）。不含 `%d` 的普通事件（如 fallback 原版音色）无 note-off
- 配置热重载：`/chord reload` → 重新下发 sync，客户端立即生效
- 力度分层采样与滑音等表现力仍留待 V2

### 7.1 乐器家族扩展（0.4.0：吉他、贝斯、架子鼓）

前三种乐器（口琴/钢琴）验证了「锚点采样 + voices 分层路由」管线的通用性，0.4.0 用同一管线扩三种：

**拨弦类（guitar / bass，手持 item 乐器）**——与钢琴同构：锚点采样三层 + `%d` 逐半音事件 + `release-mode: decay`（拨弦自然衰减，`K` = 手掌闷音）。吉他锚点 C3/E4/G5、音域 E2~E6（[−20,+28]）；贝斯锚点 C2/E3/G4、音域 E1~C5（[−29,+12]，低层 base-pitch 4.0 = 采样低中心音 24 半音的换算值，窗口内最终 pitch 恒在 [0.5,2.0]）。MIDI 导入目标域仍是全局 [−12,+25]，超出贝斯音域的高音在播放时被服务端音域校验丢弃（贝斯谱建议自行移调）。

**打击乐（drums，世界装置乐器）**——与钢琴同走 world 乐器链路（CraftEngine 家具 world-bind / `/chord piano spawn drums`），但路由语义不同：

- **12 半音 = 12 个鼓件，按八度周期重复**（[−12,23] 三个副本）。半音只用来选鼓件，不做变速——voice 行 `fixed: true` 使 `pitchFor` 恒等于 base-pitch，否则同一军鼓会被半音偏移「变调」成低音军鼓/高音军鼓
- 鼓件事件是**无 `%d` 的一次性采样**（kick/snare/rim/hat.closed/hat.open/hat.pedal/tom.high/tom.mid/tom.floor/crash/ride 各一条）：不进活跃音表 → 不受「同时持续音上限」约束（鼓滚奏需要连发，仍受每秒限速）、无逐音止音（`K` 对鼓无效，开镲/镲片自然衰减完）；中嗵 = 高嗵采样 base-pitch 0.891（−2 半音复用当独立鼓）
- **鼓件名 HUD**：voice 行 `label: "大鼓"` 随 sync v4 下发，客户端显示名回退链 = 直排音自定义名 → 服务端区间标签（鼓件名）→ 音级名（低1/高2♯）。打击乐布局对音级名不可读，这是可玩性的关键
- 默认键位（8 个音级键恰好给 8 个主鼓件）：`Z`大鼓 `X`小鼓 `C`闭镲 `V`开镲 `B`高嗵 `N`低嗵 `M`叮镲 `,`大鼓(副位)；半音位给 副鼓/鼓边/踩镲/中嗵/重镲
- 乐谱书在鼓上自动演奏 = 音高映射打法（每个音高触发对应鼓件）；录音/移调等既有机制对鼓透明生效（BPM 估算、同半音截断等都按半音工作）

**吹奏类（suona 唢呐，手持 item 乐器，0.9.0）**——与口琴同构（`release-mode: stop` 气息停即止音、`%d` 逐半音事件、fallback 原版音色），采样来源特殊：调研确认无现成 CC0 唢呐采样库（商业 Kong Audio 不免费；freesound 登录墙属已排除通道；GM Shanai 补丁授权来源不清），素材为 `tools/suona-synth.py` **原创合成**——带限锯齿加法合成 + 喇叭口共振峰整形 + 打音上滑起振 + 迟起颤音，固定种子可复现，授权随仓库；日后拿到真人录音按 harmonica-rebuild 流程替换，voices/base-pitch 由脚本重新生成。11 锚点 C/E/G 网格 C4~G6（[0,+31]，高音主奏定位，最大拉伸 ±2 半音）；p/f 力度层未做（包体预算），需要时照 violin 层结构扩展。

## 12. 决策记录

第一轮（2026-10-06）：
- 版本：Java 26.2；服务端 Folia 26.2
- 音色映射可配置化；物品识别基于 `minecraft:custom_data` 组件
- 操作复刻三角洲键位

第二轮（2026-10-06，需求锁定）：
- **加载器：Fabric（已确认）**
- **键位：默认三角洲布局，全部可重映射**（V1 配置文件，V1.1 游戏内界面）
- **音色：服务器自定义资源包承载，全音域分层采样设计**（§7）；音频资产与分发归服务器，本项目只定命名规范+配置路由
- **进入演奏态：手持乐器右键举起**；退出：蹲下或切换快捷栏
- **和弦：开放**，同刻并发上限默认 6（可配）
- **V1 乐器：仅口琴**，多乐器走配置扩展（V1.2）

第三轮（2026-10-07，乐谱与自动演奏）：
- **乐谱格式自研（CHSC v1，§13）**：谱面存成书 custom data（Base64 二进制），书页文本仅展示；不用 .nbs——MIDI 是更通用的源头格式，转换器自研纯 Java 实现（不依赖 javax.sound.midi，Paper 裁剪运行时可能不含）
- **自动演奏走既有音符协议**（同 chord:play、同校验/限速/屏蔽），加 `auto` 标记位 + `chord:auto` 会话通告；不做服务端代播——聆听者听感与人工演奏完全一致，也不给服务端引入新的调度面
- **演奏必有可见反馈**：每个 note-on 在演奏者头顶冒按音高着色的音符粒子；自动演奏用金色音符+白光+起止爆发区分（纯特效，不做聊天广播——听不到的玩家不该被打扰，用户 2026-10-07 明确）

第四轮（2026-10-07，乐器家族：吉他/贝斯/架子鼓，0.4.0）：
- **拨弦类复用钢琴管线**（锚点采样 + 逐半音事件 + decay），零协议改动；`fixed` voice 位与鼓件 `label` 是仅有的路由/协议扩展
- **打击乐映射而非变调**：鼓件 = 半音区间 → 固定音高采样（`fixed: true`），12 半音一周期；不做「半音变调鼓」——同一军鼓被变调听起来像另一件乐器，违背直觉
- **鼓件名走协议而非客户端硬编码**：布局由服务端 instruments.yml 定义，显示名必须同源（sync v4 标签规则），否则改布局后 HUD 与实际鼓件错位
- **鼓件不受和弦上限约束**：无 %d 事件不进活跃音表，上限本就只管「按住持续发声」的音；鼓滚奏需要连发，限速（25/s）仍兜底
- **鼓 = 世界装置**（与钢琴同链路）：架子鼓体积大、需双手、演奏时面向它，手持形态不合理；`/chord piano spawn` 保留命令名（世界乐器管理命名空间）但接受乐器键参数

第五轮（2026-10-07，钢琴延音踏板，0.5.0/协议 v5）：
- **真钢琴默认是制音，不是延音**（用户实测反馈：没有「止音踏板」这种东西，右踏板是延音踏板）——0.3.0 的「钢琴永远自然衰减 + K 瞬时止音」语义颠倒，重做为三态 release-mode：stop / decay / sustain
- **松键制音带 150ms 落弦缓冲**：瞬间硬切在钢琴采样上是「数码味」的主要来源；缓冲期间同半音重击（制音器先落弦再击弦）或踏板踩下（接住余振）都会取消制音，与修饰键宽限窗口同值
- **踏板是 hold 而非 trigger**：chord:pedal 上下行事件 + note-off bit3（sustain 松键）；服务端无踏板状态机，全部由事件驱动（踩下=接住制音缓冲、松开=掐余音表），无状态路径最短
- **吉他/贝斯/鼓保持 decay**：拨弦/打击乐的自然衰减是乐器本身属性（无踏板的乐器），K = 手掌闷音；只有钢琴走 sustain

第六轮（2026-10-07，表现力管线第一弹：力度，0.6.0/协议 v6）：
- **协议只承载音乐事实、不承载输入手势**（解耦铁律）：velocity 是「这个音多强」的音乐事实；
  「滚轮调到 76」「磁轴行程 40%」都是客户端手势，服务端永不知道输入来源。磁轴键盘（V2）与
  MIDI 键盘届时都只是往客户端内部事件总线上插适配器
- **力度双通道**：layers 分层采样（钢琴 vl2/vl3/vl4，同锚点实测 ≤6c 不校正）路由音色 + 音量缩放
  （100=基准）。默认力度 100 保持历史响度不变；127 允许 ×1.27 轻度过冲当重音
- **滚轮力度（普通键盘的过渡方案）**：演奏态滚轮全局调档并拦截原版滚轮（否则切快捷栏会退出演奏态）；
  磁轴真力度到来后同字段即插即用
- **踏板模式锁（双击 K）与八度锁（双击左/右键）都是纯客户端手势**：踏板锁=有效延音 XOR 键按住，
  复用 chord:pedal 与 FLAG_SUSTAIN 语义零协议改动；八度锁=修饰偏移加法（锁+按住修饰=低低/高高音），
  宽限变调窗口自动兼容。双击窗口 400ms，修饰键边沿检测在 tick（50ms 粒度足够）

第七轮（2026-10-07，演奏输入统一自管，0.7.0）：
- **音级键/直排音的区分是历史包袱**（0.6.0 后两者行为已完全一致：基础半音+修饰键叠加），
  0.7.0 合并为统一键槽（24 槽，槽=物理键+半音+显示名），配置页是唯一入口
- **不再注册原版按键设置条目**（除打开配置页的 J）：KeyMapping 的价值只有「原版 UI 改键」，
  而演奏键本就在分发源头拦截消费；自管后 GLFW 键码直配，页内按键捕获（Delete 清除、同键去重、
  后绑优先），chord.json 持久化（键名用 InputConstants 规范名 key.keyboard.z）
- **八度锁从双击鼠标手势改为独立按键**（用户反馈：手势与修饰键手势重叠、误触；默认 I/U 可配置）——
  手势方案保留在 git 历史，独立按键语义无歧义且可配置性完整
- 功能键四件套（自动演奏 G/踏板 K/高低八度锁 I/U）全部页内可改；踏板模式切换保留「双击 K」
  （它是踏板键自身的模式而非独立功能，天然属于同一个键）
- 迁移：旧 chord.json direct_notes 的半音/显示名自动并入第 9 槽起；原版 options.txt 里的旧键绑定
  随 KeyMapping 注销而失效，需在页内重按一次（开发期可接受）

第八轮（2026-10-07，客户端 MIDI 直播 + 粒子跨构建兼容，0.7.3）：
- **MIDI 文件播放走自动演奏通道**：客户端复用 MidiConverter（纯 Java、双端共用）本机转谱，目标音域取当前乐器 def 音域；scoreFromMidi 标记豁免三处「副手乐谱书」守卫（tick/autoNoteOn/toggle）。不做独立播放通道——AUTO 标记 + chord:auto 会话让服务端零改动按自动演奏展示（需求原文）
- **入口 = G 键的自然回落**（无乐谱书时打开文件选择屏 config/chord/midi），不新增键位
- **NOTE 粒子按数据类型自适应**：Particle.NOTE.getDataType()==Float 的构建传色相 data；==Void 的构建（shiroha-26.2 实测抛 IllegalArgumentException）改走 speed 携带色相（客户端按 speed×24 取色相下标）；静态一次判定

第九轮（2026-10-07，MIDI 复音容量，0.7.5）：
- **真弹录音丢音根因**：电钢琴直录 MIDI（十指 + 踏板）物理复音 7+，超过 MidiConverter 自动
  模式的收敛阈值 6（DEFAULT_MAX_POLYPHONY，口琴时代口径）→ 强制单旋律、同刻和弦只留最高音
  ——左手/内声部整只消失；编排类 MIDI 复音 ≤6 不触发，故「别的 MIDI 不丢」（实测样本：
  416 音 / 复音 7 → 收敛后剩 275）
- **复音容量成为乐器属性**（instruments.yml `max-polyphony`，默认 6；钢琴 10），经 chord:poly
  独立频道随 sync 下发；convert 增加 maxPolyphony 参数按乐器判决
- **兼容性决定不进 sync**：旧客户端 SyncPayload.fromBytes 严格拒载荷多余字节，追加字段 =
  已发布客户端整表失败；独立频道旧客户端静默忽略。旧服务端（不发 poly）时客户端兜底：
  sustain 乐器按 10、其余 6——即只升客户端 0.7.5 也能修钢琴丢音

第十轮（2026-10-07，CHSC v2 力度进谱，0.7.6）：
- **MIDI 播放此前无强度控制**：CHSC v1 每音只有时刻+音高+时长，转换器解析即弃力度，
  autoNoteOn 固定发 100；线协议 velocity（v6）与服务端力度层反而一直闲着
- **v2 = 每音追加 u8 velocity**（1~127，100=基准）：读端兼容 v1（回填 100，旧书响度不变，
  永久可读）；转换器全程携带（开音表从 Map<Integer,Long> 变 OpenNote(tick,velocity)；
  收敛取最高音力度）；autoNoteOn 逐音发送；服务端录制同步捕获真实力度（滚轮档/磁轴将来
  录的谱带走强弱）；MIDI 播放提示显示力度范围
- **代价**：v2 书在旧客户端（≤0.7.5）不识别（视为无谱书，不自动演奏）——新客户端读旧书
  无碍；线协议零改动（velocity 字段 v6 已有），纯客户端 0.7.6 + 任意 ≥0.6.0 服务端即得
  MIDI 力度（服务端 0.7.6 另得「录制带力度」）

第十一轮（2026-10-07，钢琴收音听感，0.7.7）：
- **松键「戛然而止」根因**：MC 声音引擎对播放中的声音只有「立刻停/不管」两态、无音量包络，
  松键制音走 stopSound 硬切；真钢琴制音器落弦是 100~300ms 快速衰减。修法 = **release-voices
  制音尾音**：硬切后对同一听众快照叠加同音高真实收音采样（VCSL 同 patch Rel/ 目录 NoSusRel，
  无踏板演奏录音），音量 = 主音 × 0.75 × 力度缩放；叠加点仅松键制音/松踏板/闷音键，不叠在
  同半音重击、余音淘汰、掉线收尾
- **主采样加长**：2.5s 定长 + 0.3s 淡出会在可闻段掐断长音/踏板音 → 静音门控自然衰减
  （相对 −45dB），低/中音 6s 触顶、高音自然衰尽（1.4~5.5s，高音弦物理衰减快）
- **服务端和弦上限改为按乐器**：原 config 全局 limits.max-simultaneous-notes=6 仍在
  note-on 处拦截（0.7.5 时误判「服务端无上限」——7 复音曲第 7 音仍被丢）；0.7.7 起该处
  改用 instrument.maxPolyphony，与客户端转换阈值同源，配置项移除

第十二轮（2026-10-08，制音尾音三档 0.7.8 + 无缝结论）：
- **尾音叠加结构性不可无缝**（用户追问「确定能完全无缝吗」后的诚实结论）：引擎对播放
  中的声音无音量包络——硬切点（任意相位归零）、新旧声音相位差、档位粒度差三重接缝消不
  掉。0.7.8 三档天然电平把 0.7.7 固定归一的 +7~10dB 跳升压到 ±3dB，属「明显改善、非绝对
  无缝」，以试用版交付，回滚预案 = 仅换回 plugin-0.7.6.jar（release-voices 被忽略即回
  纯硬切，6s 长采样保留）
- **完全无缝的唯一路径（待用户拍板）**：「制音采样」架构——默认（不踩踏板）音符改用
  自带 ~1.5s 天然结尾的采样（Sus 前 0.8s 原样 + 后 0.7s 烘焙陡衰减），松键**不做任何
  停音**（声音自己播完 = 结构上不存在接缝）；踩踏板用现有长采样；同半音重击仍先停旧音
  （接缝被新起振遮蔽）；松踏板掐余音维持 stopSound（真实「落闸」瞬间）。代价：默认音符
  结束为固定长度、踏板中途接住语义弱化、包 +~300KB

第十三轮（2026-10-08，MIDI 踏板延音，0.7.9）：
- **用户报「MIDI 放出来没有延音、很生硬——有手按住的延音、没有踏板的延音」**：根因=
  转换器把 CC64 事件直接跳过（谱里只有按键时长），踏板期间松开的音全按松键制音。样本
  曲实测 1094 个 CC64 事件、踏板语义下最大同时发声 85——重踏板演奏被完全抹平
- **修法 = 踏板烘进音符时长（零协议/零格式改动）**：键松开落在踩下区间（CC64≥64，
  按通道跟踪）→ note-off 延至踏板抬起；CHSC 本就只存「发声起止」，服务端零感知。
  客户端按乐器 sustainPedal 开关（钢琴开，口琴等不动）；实测样本曲 2299 音中 2198 个
  被延长、总发声 635s→2405s
- **两个关键坑**：①旋律收敛判定必须用**物理**复音（延长后谱面复音可达 85，按它判会把
  踏板曲误收敛成单旋律）；②服务端活跃音上限对 sustain 乐器放开（踏板延音把松开的音
  留在活跃表合法堆叠，十指上限会丢音；活跃表按半音建键天然有界，滥用由限速器约束）
- 已知边界：文件末尾仍踩着的踏板按 +1500ms 兜底；同半音踏板下重击**截断旧音保留新音原起点**
  （活跃表按半音建键，同音不可叠）。**0.7.10 修复**：buildNotes 的同音重叠处理原实现是
  「推迟新音起点」（注释写截断旧音、代码却挪新音）——踏板时代前重叠仅毫秒级无感，踏板
  把旧音延长到秒级后，同音重击被整体推迟到踏板抬起之后，表现为「随机吞音/错位」
  （用户实测反馈）；修=真按语义截断旧音（引擎单声部，重击=制音器随新击弦落下），仅
  极快重击（<40ms）保留顺延兜底。回归验证标准：**踏板开/关双跑，每个音符起振点必须
  逐音一致**（踏板只准延长不准挪动；两份实测曲 0 位移）

## 13. 乐谱（内存谱）与 MIDI 转换器

**CHSC 二进制格式已随乐谱书移除（0.7.15）**：谱不再持久化——`.mid` 每次播放经
MidiConverter 现转为内存 `Score` 对象（曲名/BPM/拍号/移调/升序音符表：startMs、
pitch（相对 C4）、durationMs、velocity 1~127），用完即弃。历史上的成书载体
（CHSC v1/v2 大端布局 + varuint Δ 编码 + Base64 入 PDC `chord:score`）只留本节存档；
存量乐谱书物品在新客户端按普通成书处理。

**MIDI 转换器**（`chord.protocol.score.MidiConverter`，自研解析不依赖 javax.sound.midi）：
- 支持 SMF format 0/1（多轨按绝对时间合并）、running status、tempo map（变速谱时间精确烘焙毫秒）、拍号事件、**CC64 延音踏板**（0.7.9，sustain 乐器播放时烘焙进音符时长：键松开落在踩下区间内 → note-off 延至踏板抬起；旋律判定仍用物理复音——延长后的谱面复音可达数十，按它判会把踏板曲误收敛成单旋律）；音色丢弃（由服务端乐器决定）；**力度逐音保留**（单音收敛取和弦最高音的力度）
- 前导静默裁零；时长 <30ms 夹到 30ms；同音高重叠音强制 10ms 间隔（服务端活跃音表按半音建键）
- **跨轨去重（0.7.13）**：(startTick × 128 + pitch) 同键音符跨轨合并（保留较长 end、较高力度及其 channel）——同一演奏写两轨的导出工件（如本次 La Campanella）不去重会让复音统计翻倍
- **单音收敛（旋律乐器）**：物理复音超过该乐器容量（chord:poly，默认 6）自动收敛——同刻（±12ms）和弦取最高音、长音在下一 onset 截断；**sustain 乐器（钢琴）永不收敛**，改为瞬时封顶（0.7.13）：复音尖峰时刻只截短最快结束的余音（保留全部声部与起振，物理十指语义）
- **移调自动适配**：-12~+12 全量搜索「目标音域内音符数最多」的偏移（|t| 小者优先，目标域取当前乐器 sync 音域）
- **八度折叠兜底**：移调后仍出界的音按 ±12 折叠入域（只动八度不动调内位置），折叠够不着的丢弃并计数——保证任何常规 MIDI 转出的谱 100% 可演奏；音符数与整谱时长**无上限**（0.7.13 起移除 5000 音/15 分钟旧限）

## 14. 演奏特效与自动演奏提示

**音符粒子**（`effects.note-particles`，默认开）：每个 note-on 服务端在演奏者头顶 +2.0 格发 1 个 `NOTE` 粒子（count=1 + Float 色相数据），色相按半音线性映射（-12~+25 → 0~24），附近所有玩家可见。粒子统一经演奏者**实体调度器**投递到其区域线程再发送（Folia：粒子是区块跟踪者广播，不能在任意线程调）；发送失败 WARNING 告警一次后静默。

**自动演奏区分（`effects.auto-particles`，默认开，纯特效零聊天刷屏）**：
- 自动音符一律**金色音符**（固定色相）+ 每音一缕白色 `END_ROD`；人工演奏 = 音高色相纯音符——看得见的人一眼分辨
- `chord:auto` START/STOP 时头顶爆发一簇三色音符 + 白色光点（开始大簇 8×3、结束小簇 4×3）
- **不做任何聊天栏/actionbar 广播**：听不到的人完全不被打扰（用户明确要求）

防滥用口径不变：自动音符与手动同限速/同和弦上限/同屏蔽（`/chord mute`）——自动演奏不是绕过手段。
